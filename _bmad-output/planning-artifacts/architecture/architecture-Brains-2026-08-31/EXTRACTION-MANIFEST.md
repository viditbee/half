> **Note on the 24-hour window — the reference does not solve this problem, it avoids it.** hermes's own comment is explicit: its interactive senders "only work *inside* the 24-hour conversation window — which is fine because all five senders below fire in direct response to a user message… so we're always inside the window when they're invoked." It tracks `_last_inbound_wamid_by_chat` for reply context, not for window arithmetic, and never has to choose between free-form and template.
>
> **Half is routinely outside the window by design.** The morning surface, loop revival and every nudge are unprompted contact. So there is nothing to port here — the window logic has to be built, and AD-7's `capability_query` is not a convenience but the thing that makes unprompted contact legal at all.
>
> What *was* taken: the adapter interface shape (abstract `connect` / `disconnect` / `send` / `get_chat_info` plus declarative capability flags like `supports_code_blocks` and `supports_status_text`, so presentation differences stay in the adapter), and the typing-heartbeat pattern with its per-chat pause set and status-text dict refreshed on the existing cadence rather than by extra API calls.

That state has no counterpart in graphiti and it is why the split earned two nullable fields rather than one enum: an enum with three values would have had to be *chosen*, and `half/correction/attribute.py` is built so that nothing chooses. Rejected: `created_at`, which is already every record's `t` — a second field for it is a second place for the log's own ordering to disagree with itself; and `valid_at`, *when the claim became true*, which no producer in Half supplies. Beliefs arrive from conversation and ingestion with no date the claim started holding, and a field empty on every record is a field that invites being filled with a guess — `tests/test_attribution.py` asserts by AST that neither name is a field of any record, so adding one is a deliberate edit with a failing test on it. Also rejected: graphiti's **edge-level mutation** of those timestamps. Half never edits a record, so a cause that arrives later is an *append* naming the same target, and the current attribution is folded from the log (never materialized) for the reason the trust balance is — the belief it describes has left the fold, and there is nowhere in the derived view for a cause to hang on |
| Edge resolution returning `(resolved, invalidated, new)` | `graphiti_core/utils/maintenance/edge_operations.py` | 9d — tension minting | ✅ **the outcome shape and the escape hatches taken; `invalidated` rejected outright.** Lifted into `half/consolidate/mint.py`. **Taken 1 — three outcomes rather than a list of creations.** `resolve_extracted_edges` returns `(resolved, invalidated, new)`, and the insight is that one pass over a candidate set does not produce *creations*: it produces creations, things that already existed, and things it decided against, and reporting only the first makes the other two indistinguishable from nothing having happened. `MintResult` carries `minted` / `standing` / `passed` as three disjoint tuples, plus `unsaid`, `skipped` and `unrecorded` — kept apart because *“the judge said no”*, *“the judge could not say”*, *“the judge raised”* and *“no judge is wired”* would otherwise be one assertion satisfied by the port never being reached at all. **Taken 2 — the escape hatches *before* the model**, which is what actually bounds graphiti's cost: it skips the LLM entirely when a candidate has no related edges, and short-circuits on an exact normalised fact match against an edge it already holds, which is its idempotence guarantee for re-ingesting an episode paid for with zero calls. ## HippoRAG — retrieval gating

| What | Where | For story | Status |
| --- | --- | --- | --- |
| Recognition-memory filter pruning candidate facts **before** expensive traversal | `src/hipporag/rerank.py` (`DSPyFilter`) | 9d — bounded tension minting (AD-9), 4 — retrieval | ✅ **both stories now — and the load-bearing finding is that `DSPyFilter` is not the cheap filter.** Reading it for story 9d is what settled the design, mostly by relocating the thing worth taking. `DSPyFilter` is *one LLM call per query, unconditionally*: a DSPy-compiled few-shot prompt at `max_new_tokens=512`. The pruning that makes it affordable happens **upstream** in `HippoRAG.rerank_facts`, which `np.argsort(query_fact_scores)[-link_top_k:]` down to `linking_top_k` — default **five** — before the model sees anything, and passes the same number as `len_after_rerank` so the expensive step can reorder and drop but never expand. **Taken: that placement.** `half/consolidate/relevance.py` is the cheap non-model narrowing and `half/consolidate/port.py` is the one expensive step, and `mint.slate` computes the whole survivor list and cuts it to `JUDGEMENTS` *before* a single call is made, so the judge cannot widen what it was given. Also taken: its three fail-soft layers — an exception in the expensive step yields an empty result rather than an error, and the caller proceeds — which is `mint.consider` catching per couple and counting the skip. **Rejected 1 — the filter itself**, which is a model call this story forbids outright (*no model call in this story, and no provider wired into the composition root*). Half's three cheap rules are decidable offline: both halves must carry a claim, the two must not sit on the same named ledger (the mirror *is* the gap between the two ledgers), and the two must not be restating each other under `half.text.tokens`. **Rejected 2 — `difflib.get_close_matches(..., cutoff=0.0)`**, already rejected once in story 4 and rejected again here for the reason it was then: a cutoff of zero always returns a nearest string, so a filter built on it can never say *nothing survived*. **Rejected 3 — lexical overlap as the relevance test**, which is what a first reading of *recognition memory* suggests and is exactly wrong for this domain. HippoRAG's candidates are facts about a query and share its vocabulary; Half's canonical tension is *“means to buy the farmland this year”* against *“has not opened a listing since March”*, which share no word at all. A shared-term gate would have rejected precisely the pairs CAP-7 exists to mint. **Rejected 4 — a percentile cut** (`TOP_PERCENT_SURPRISAL` in its sibling below): a percentage of a candidate set is not a cost bound, and the cost bound is what CAP-7 asks for.
