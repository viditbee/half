- (insight) KEY FINDING — SINGLE WRITER MAKES THE FILE-BASED LAW AFFORDABLE. claude-obsidian needs heavy transaction machinery because parallel agents write one vault. Half has exactly ONE main and ONE Half, so there is exactly one writer per main by construction. Append-only JSONL under a single writer largely dissolves the multi-file atomicity problem that forced their journal/rollback layer
- (insight) KEY FINDING — ONE MAIN = ONE DIRECTORY = ONE EMBEDDED INDEX. Per-main isolation (rather than khoj/honcho shared multi-tenancy) satisfies sovereignty, trivial export, real expunge, and self-host-equals-hosted in a single decision: the hosted product is the self-hosted product, many times over. SQLite FTS5 supplies BM25 with no server and no vector service, satisfying the retrieval constraint
- (decision) AD-1 PARADIGM (user chose the coach's lean): event-sourced SINGLE-WRITER ACTOR PER MAIN, whose core is a local-first library operating on one directory. Binds: every unit that mutates a main's state. Prevents: two components writing one main's store concurrently, and a hosted implementation diverging from the self-hosted one. Rule: all mutation for a main is serialized through that main's single owner; the hosted product is a supervisor running many actors, self-host is one actor — same code, never a stripped variant. Alternatives weighed: stateless handlers + shared queue + Postgres (honcho) rejected because a shared DB breaks per-main isolation, makes export a serializer rather than a copy, reintroduces the multi-file transaction layer, and strains 'no managed service required'; pure local-first CLI (gbrain/claude-obsidian) rejected alone because a companion needs an always-on receiver
- (decision) AD-2 LANGUAGE/RUNTIME: Python. Binds: every unit. Prevents: a polyglot split between gateway and core, and reimplementing solved surfaces. Rule: Python throughout; async via asyncio. Chosen for direct reuse of production-quality Python solutions to Half's two hardest v1 surfaces — hermes-agent's BasePlatformAdapter plugin contract (messaging gateway) and claude-obsidian's ledger + file-transaction primitives. TypeScript (gbrain) weighed and rejected despite a materially better npx self-host install; Go/Rust rejected as too slow to first build. User explicitly accepted the tradeoff: packaging/distribution is a solvable later problem, not an architectural one
- (assumption) Python distribution for self-hosters is deferred to packaging work (uv-based); if adoption friction proves first-order this becomes a revisit condition on AD-2, not a rewrite
- (decision) AD-3 STORAGE LAYERS: four layers per main — (1) sources/ content-addressed immutable files; (2) beliefs/YYYY-MM.jsonl append-only event log, THE SOURCE OF TRUTH; (3) loops/*.md and people/*.md markdown+YAML projections; (4) one SQLite file per main holding the materialized fold plus the FTS5 index. Binds: every unit that reads or writes state. Prevents: two components disagreeing on which representation is authoritative, and an export that needs a serializer. Rule: the JSONL log is the only authority; SQLite and every projection are derived and disposable. Alternative rejected: SQLite as the log with files as export — makes the truth binary, turns export into a serializer that must be kept correct, and dissolves the file-format-as-standard moat
- (decision) AD-4 THE REPLAY INVARIANT (user explicitly endorsed): deleting a main's SQLite file and replaying their JSONL log must reproduce byte-identical state. Binds: every unit that writes derived data. Prevents: a derived store silently accumulating state that exists nowhere in the log — which would break export, expunge, and rebuild-after-model-churn simultaneously. Rule: no state may exist only in SQLite or only in a projection; replay equality is a CI test, run per commit, not a convention
- (decision) AD-5 INDEX TECHNOLOGY: SQLite FTS5 for BM25 retrieval — embedded, no server, no vector service, satisfying CAP-9's success criterion directly and the no-managed-service constraint. Binds: the retrieval unit. Prevents: a vector database creeping into the hot path. Rule: the hot retrieval path is FTS5 BM25 over the belief set; any reranker or embedding model is optional and must degrade to correct results when absent. Note: claude-obsidian hand-rolled stdlib Okapi BM25 (k1=1.5, b=0.75) to avoid a dependency; FTS5 ships in Python's stdlib sqlite3 and is faster
- (note) Named tradeoff on AD-3: two representations of the same data means drift is a real bug class. AD-4's replay test is the enforcement, but it is discipline plus CI rather than a structural guarantee
- (decision) AD-6 GATEWAY: build clean and own the runtime; PORT specific well-tested modules from hermes-agent (MIT, attribution preserved) rather than adopting or forking it. Binds: the channel layer and the actor loop. Prevents: Half's control flow becoming a guest inside a host agent runtime. Rule: no agent-runtime dependency; real dependencies are official platform SDKs only (python-telegram-bot, Meta Graph API over httpx). Rationale: hermes's MemoryProvider interface (prefetch before a turn, sync_turn after) assumes memory DECORATES a turn that will happen — Half's thesis is deciding WHETHER the turn happens, so silence, licenses, the unsaid queue and the crisis pre-filter would all be constraints fighting the host's loop. Forking rejected: inheriting a large actively-developed runtime's maintenance surface to use ~5% of it, diverging from upstream immediately
- (decision) AD-7 THE CHANNEL PORT (user confirmed): four operations — receive, send, draft-link, and CAPABILITY-QUERY ('may I send an unprompted message to this main right now?'). - (decision) AD-8 ACTOR PROCESS MODEL: an actor is an INBOX PLUS A MUTEX keyed by main_id — not a process, not a task. Binds: the runtime host. Prevents: per-main process overhead that makes dormant users expensive, and a second enforcement mechanism for single-writer. Rule: one worker process hosts many actors; a dormant actor is a dict entry, hydrated on demand (open SQLite + read the fold snapshot, single-digit ms, dwarfed by the model call); hibernation IS eviction from the LRU
- (decision) AD-9 NIGHTLY PASS SCHEDULING: a DUE-TIME QUEUE with bounded concurrency, never a global cron. Binds: the consolidation scheduler. Prevents: a thundering herd. Rule: each main carries next_pass_at set to their local pre-dawn with jitter; the scheduler drains what is due. Submitted via the BATCH API (50% cost, no latency requirement) at ~8pm local for a ~7am delivery, giving ~11h of slack; if a batch misses its window Half sends NOTHING, which the spec already permits. - (decision) AD-10 CRISIS PRE-FILTER PLACEMENT (inversion): the crisis module OWNS THE INBOUND ENTRYPOINT and delegates inward; the normal pipeline is something crisis CALLS and has no other caller. Binds: every inbound path. Prevents: a crisis check being refactored around, which a mere function call invites. Rule: one call site into the pipeline, enforced by an architecture test. Stated honestly: Python cannot structurally forbid a direct import — inversion plus a single enforced call site is the strongest available guarantee, not a proof
- (decision) AD-11 SECRET BOUNDARY (Mary's catch): the EXPORT BOUNDARY AND THE SECRET BOUNDARY MUST NOT OVERLAP. Binds: credential handling and export. Prevents: shipping a live OAuth refresh token inside the zip the main downloads, and replay resurrecting a revoked credential. Rule: per-main credentials live entirely OUTSIDE the four layers — never in the log, never in a projection, never in replay, never in export. Self-host uses OS keyring or an env-keyed encrypted file; hosted uses envelope encryption (per-main data key wrapped by a master key). Note: CAP-13 covers secrets FOUND IN SOURCES; this covers secrets Half was GIVEN — two different things, one word
- (decision) AD-12 DEPLOYMENT ENVELOPE: same code, two shapes. SELF-HOST — one process, one actor, Telegram long-polling (no public URL needed), SQLite and all four layers on local disk, main's own API keys in env. HOSTED — the same process type with many actors, plus a router and the due-time scheduler, SHARDED AND PINNED (each node owns a set of mains; routing maps main_id to shard; rebalancing is a deliberate drain-and-move). Binds: infra and ops. Prevents: a hosted implementation diverging from the self-hosted one, and an autoscaler moving an actor away from its disk. Rationale: per-main directories make actors sticky — object-storage-as-home was rejected because it turns an atomic O_APPEND under a single writer into a read-modify-write against an eventually-consistent store, reintroducing the transaction layer AD-3 avoided
- (decision) AD-13 SOURCE STORE PORT: layer 1 (sources) is big, immutable and read only during ingestion or rebuild, so it gets its own port — local filesystem for self-host, S3-compatible object storage for hosted. Layers 2-4 (log, projections, SQLite) always stay local to the actor's node. Binds: ingestion and rebuild. Prevents: the sticky per-node footprint growing without bound. Does not violate 'no managed service required' — that constraint governs CORE CAPABILITY, and self-host loses nothing on local filesystem
- (decision) AD-14 BACKUP AND RESTORE: the append-only log makes incremental backup free — ship new segments, never re-upload history — and point-in-time restore is a consequence of replay rather than a feature. Binds: the hosted operator. Rule: per-main segment shipping with fsync on append. Stated tradeoff: a node lost with unshipped segments loses the tail; fsync plus frequent shipping shrinks the window without closing it
- (decision) AD-15 OUTAGE AWARENESS (Sally's, user approved, IN SCOPE FOR V1): downtime is recorded in the main's own log, not hidden in ops. Binds: the actor's wake path. Rule: on wake after an outage exceeding a threshold, Half's first message accounts for its absence before anything else. Rationale: sharded-and-pinned means an outage takes out a NAMED GROUP of humans rather than degrading a percentage of requests — an assistant need not explain itself, a half does

- (decision) AD-18 TWO-CHANNEL CONTEXT (the session's central insight, user endorsed): licenses are enforced at CONTEXT-CONSTRUCTION time, not by post-generation filtering.
